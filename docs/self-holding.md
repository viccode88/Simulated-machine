# 設備自持（self-holding）設計

## 1. 為什麼把控制放進設備

舊架構有一台內建 DCS：它跑 5 個 PID 迴路、一套 16 步冷啟動順序，透過 Modbus 把
輸出寫進設備。缺點是整廠只要控制器一離線就停擺，而且「設備」與「控制」的界線
其實只是網路距離。

現在的分工是：

| 角色 | 負責 | 不負責 |
| --- | --- | --- |
| 設備 | 啟停判斷、閉迴路調節、保護跳機、互鎖 | — |
| PLC（OpenPLC v3／v4） | 資料交換、watchdog、脈衝展寬、跳機矩陣、互鎖判斷 | 任何控制運算 |
| SCADA／HMI | START／STOP／ACK／RESET、觀察 | 設定值與輸出 |

好處：

* 控制與物理在同一個 scan cycle，控制週期永遠等於 dt，模擬加速也不會失步。
* 沒有 PLC、沒有 SCADA，機組照樣自己併聯發電（`COMPOSE_PROFILES=no-plc` 可驗證）。
* PLC 與 SCADA 的攻擊面變成「命令」而不是「控制值」，資安演練的因果更清楚。

## 2. 自持狀態機

每個 scan cycle，`BaseDevice._self_hold_step()` 在物理之前執行：

```
維修模式          → SELF_HOLD_STATE = 5 MAINTENANCE，不自動啟動
跳機／鎖存／急停  → 4 TRIP_LOCKED，必須先 RESET_TRIP
操作員 STOP 過    → 3 OPERATOR_STOP，必須再按一次 START
運轉中            → 2 RUNNING；本地需求消失超過 self_restart_delay_s 就自行停機
停止中            → 1 STANDBY；允許條件 + 本地需求連續成立 self_start_delay_s 後自行 START
自持關閉          → 0 DISABLED（SELF_HOLD=false）
```

兩個判斷來源分得很清楚：

* `start_permissives()` — **可不可以跑**（安全與環境條件，同時決定 `READY`、
  `INTERLOCKS_OK` 與 30028 `PERMISSIVE_WORD`）。
* `self_start_ready()` / `self_stop_request()` — **現在需不需要跑**（本地需求）。
  例如泵浦的下游水位已經高於設定值時就不需要送水。

**操作員停機鎖**是自持設備一定要有的東西：沒有它，SCADA 按下 STOP 之後
下一個掃描週期設備就會自己再啟動，等於按不下去。因此 `STOP` 會設定
`operator_stop = True`（並持久化，跨容器重啟保留），只有 `START` 會清除它。

## 3. 各設備的本地迴路

| 設備 | PV | SP | MV | 備註 |
| --- | --- | --- | --- | --- |
| 冷凝器 | 熱井水位 | 40011（55%） | 補水閥 | 冷卻水在 AUTO 固定全開 |
| 凝結水泵 | 給水槽水位 | 40010（60%） | 泵浦轉速 | 給水泵流量前饋；水位夠就待機 |
| 給水槽 | — | — | 加熱 | 被動容器，永遠 RUNNING |
| 給水泵 | 鍋爐水位 | 40010（66.7%） | 泵浦轉速 | 三元素：水位修正＋蒸汽流量前饋−給水流量回授 |
| 鍋爐 | 汽包壓力 | 40010（100 bar） | 燃燒器 | 升壓期間限幅 20%，併聯後解除 |
| 主蒸汽閥 | 轉速／發電量 | 40010（3000 RPM）／負載需求 | 閥位 | 調速器：併聯前控轉速、併聯後控負載；升速限幅 15% |
| 汽輪機 | — | — | — | 無執行器；自持＝真空與壓力允許就自行進汽 |
| 發電機 | 負載 | 40010（60 MW） | 負載需求 | 自動勵磁、自動同步併聯、壓力不足暫停加載 |

調節器實作在 `common/device/regulator.py`：PI(D)、anti-windup、輸出速率限制、
死區、**動態輸出限幅**（限幅進到調節器內部，而不是事後 `min()`——外部限幅會讓
積分累積到上限，解除瞬間輸出跳到滿檔）、以及手動模式下的追隨（bumpless）。

所有增益與門檻都在 `configs/<device>.yaml` 的 `control:` 區塊，程式中不硬編碼。

## 4. 自持啟動為什麼會自己排序

沒有任何順序器，冷啟動順序是**允許條件互相扣住**後自然浮現的：

```
熱井有水            → 冷凝器啟動 → 抽真空
熱井 ≥ 20%          → 凝結水泵啟動 → 給水槽補到 60%
給水槽 ≥ 25%        → 給水泵啟動 → 鍋爐水位維持 66.7%
水位 30~80% 且閥關  → 鍋爐吹掃 30 s → 點火 → 升壓（燃燒器限幅 20%）
壓力 ≥ 30 bar 且真空良好 → 主蒸汽閥開啟（限幅 15%）→ 汽輪機升速
轉速 ≥ 2700 RPM     → 發電機勵磁 → 同步條件成立 → 自動併聯
併聯                → 燃燒器解除限幅、負載以 0.5 MW/s 爬向 60 MW
壓力 < 90 bar       → 暫停加載，等鍋爐追上再繼續
```

實測（`tests/integration/test_self_hold.py`）：約 930 模擬秒到達 60 MW，
壓力穩定在 99 bar、轉速 3002 RPM、無任何跳機。

## 5. 讓機組「維持在可運行狀態」的兩個關鍵動作

自持不只是會自己開機，還要在擾動之後**留在可運行狀態**、不要留下需要人工重置的鎖存。
甩載（斷路器打開）是最嚴苛的測試，兩個本地動作缺一不可：

| 動作 | 位置 | 為什麼需要 |
| --- | --- | --- |
| 超速快關 | 主蒸汽閥 | 60 MW 甩載時轉速以約 250 RPM/s 上升，正常關閥速度（100%/3 s）追不上；超過 3150 RPM 改用 fast-close（0.4 s），轉速峰值壓在 3140 RPM 以內 |
| 高壓 runback | 鍋爐 | 蒸汽需求瞬間消失，蒸發量以 20 s 的一階遲滯衰減；壓力達 108 bar 就直接切燃料（不受 10 %/s 限制），峰值壓在 115 bar 跳機門檻以下 |

實測（60 MW 甩載）：轉速峰值 3136 RPM、壓力峰值 114.6 bar、**零跳機**，
180 秒後回到 2999 RPM 空載待命，斷路器可再次併聯。

另外，發電機過頻保護在斷路器打開時被抑制——那是電網側保護，脫網後由汽輪機的
超速保護（3300 RPM）負責；否則每次正常甩載都會留下一個沒有意義的跳機鎖存。

## 6. 手動接管

需要人為介入時（實驗、測試單一執行器）：

```bash
plantctl write --device boiler --register CONTROL_MODE --value 0   # LOCAL_MANUAL
plantctl write --device boiler --register MANUAL_OUTPUT --value 35
```

AUTO（`CONTROL_MODE` = 1 LOCAL_AUTO 或 3 REMOTE_AUTO）時 40012 `MANUAL_OUTPUT`
被忽略，且設備**不會回寫自己的 Holding Register**——那些暫存器屬於操作端，
設備回寫會與 PLC 的週期寫入互相蓋來蓋去。本地調節器的輸出一律經由
30026 `LOCAL_OUTPUT` 與各設備的程序量暫存器回報。

停用整個自持功能：`.env` 的 `SELF_HOLD=false`，或 `configs/plant.yaml` 的
`control.self_hold: false`。此時設備退回純外部命令模式（仍保有保護與互鎖）。
