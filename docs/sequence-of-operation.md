# 操作順序

本頁是操作順序的摘要。逐步操作方法、錯誤判讀與排除，見
[操作手冊](operations-manual.md)；自持控制的設計見 [自持設計](self-holding.md)。

## 1. 冷啟動順序（設備自持，沒有順序器）

**沒有任何程式在排這個順序。** 每台設備只看自己的允許條件與本地需求，
順序是允許條件互相扣住後自然浮現的。下表是實際觀察到的時間軸
（`tests/integration/test_self_hold.py` 的冷啟動，模擬時間）。

| 約略時間 | 發生的事 | 觸發它的允許條件 |
| ---: | --- | --- |
| 0 s | 冷凝器自行啟動，開始抽真空 | 熱井水位 > 5% |
| 0 s | 凝結水泵、給水泵自行啟動 | 熱井 ≥ 20%、給水槽 ≥ 25% |
| 0 s | 鍋爐開始 30 秒吹掃 | 水位 30～80%、主蒸汽閥接近關閉、無跳機鎖存 |
| 35 s | 點火，火焰穩定後升壓（燃燒器限幅 20%） | `FLAME_STATUS` ≥ 2 |
| 60 s | 冷凝器真空 ≤ 0.15 bar(a) | 冷卻水全開 |
| 145 s | 壓力 ≥ 30 bar → 主蒸汽閥自行開啟（限幅 15%） | 壓力達最低進汽壓力 + 真空良好 |
| 150 s | 汽輪機自行進汽升速 | 真空良好 + 主蒸汽壓力 ≥ 10 bar |
| 220 s | 轉速 ≥ 2700 RPM → 發電機自行勵磁 | 汽輪機未跳機 + 轉速達額定 90% |
| 235 s | 同步六項條件成立 → **自動併聯** | `SYNC_PERMISSIVE` = 0x3F |
| 235 s | 併聯後燃燒器解除升壓限幅 | `generator.breaker_closed` |
| 235 s～ | 負載以 0.5 MW/s 爬升；壓力 < 90 bar 時自動暫停加載 | 鍋爐壓力 ≥ 設定值 90% |
| 930 s | 到達 60 MW 穩態（99 bar / 3002 RPM） | — |

各設備的允許條件都可以直接讀：30028 `PERMISSIVE_WORD` 每個位元對應
`start_permissives()` 的一項，30027 `SELF_HOLD_STATE` 說明目前是待機、
自持運轉、操作員停機還是跳機鎖定。

## 2. 順序禁止（會被拒絕的操作）

自持設備沒有「順序 guard」這一層了——擋下動作的一律是**設備自己的允許條件**，
判讀時只要看 `PERMISSIVE_WORD` 與 `COMMAND_REJECTED` 事件。

**設備層拒絕**（事件 `COMMAND_REJECTED`，代碼 `5x90`）：

* 跳機未重置時重新啟動設備
* 緊急停止啟動中
* 維修模式（`CONTROL_MODE`=4）
* 啟動允許條件不成立（`INTERLOCKS_OK`=0），例如：

| 設備 | 主要允許條件 |
| --- | --- |
| 凝結水泵 | 熱井水位 ≥ 20% |
| 給水泵 | 給水槽水位 ≥ 25% |
| 鍋爐 | 水位 30～80%、主蒸汽閥接近關閉 |
| 主蒸汽閥 | 鍋爐壓力 ≥ 30 bar、冷凝器壓力 ≤ 0.15 bar(a) |
| 汽輪機 | 真空良好、主蒸汽壓力 ≥ 10 bar |
| 發電機 | 汽輪機未跳機、轉速 ≥ 額定 90% |

* 發電機同步六項條件未全部成立時閉合斷路器

被拒絕的命令會：保持設備原狀、設定 `COMMAND_REJECTED` 警報、
記錄拒絕原因與被擋下的允許條件、增加 `30033 REJECTED_COMMAND_COUNT`。

（`30032` 是 `MODBUS_REQUEST_COUNT`，不要混用。）

## 3. 控制迴路（全部在設備內）

| 迴路 | 位置 | PV | SP | MV | 備註 |
| --- | --- | --- | --- | --- | --- |
| 鍋爐壓力 | 鍋爐 | 汽包壓力 | 40010（100 bar） | 燃燒器輸出 | 5 %/s 上升、10 %/s 下降、升壓限幅 20% |
| 鍋爐水位 | 給水泵 | 顯示水位 | 40010（66.7%） | 泵浦轉速 | 三元素：水位修正 + 蒸汽流量前饋 − 給水流量回授 |
| 給水槽水位 | 凝結水泵 | 槽水位 | 40010（60%） | 泵浦轉速 | 給水泵流量前饋；水位過高則進入待機 |
| 熱井水位 | 冷凝器 | 熱井水位 | 40011（55%） | 補水閥 | — |
| 汽輪機轉速 | 主蒸汽閥 | 轉速 | 40010（3000 RPM） | 閥門開度 | 死區 2 RPM、升速限幅 15%、超速無條件關閥 |
| 有功功率 | 主蒸汽閥 | 電氣功率 | 發電機負載需求 | 閥門開度 | 強電網併聯後接手，bumpless |
| 負載爬升 | 發電機 | — | 40010（60 MW） | 負載需求 | 0.5 MW/s；鍋爐壓力不足時暫停 |

自動／手動切換與轉速↔負載接手都採 bumpless transfer（以目前輸出反推積分項）。

## 4. 跳機後的處理

1. 設備自身立即執行安全動作（燃燒器歸零、快關、斷路器跳脫）。
2. 相鄰設備透過 sim_net 訊號連鎖（`turbine.tripped` → 主蒸汽閥快關）。
3. **PLC 跳機矩陣**作為第二層防護——只下命令：`BREAKER_OPEN`、對下游設備的
   `STOP` 脈衝，以及超速時對主蒸汽閥的 `STOP`。PLC 不寫任何控制值。
4. 第一故障原因寫入事件記錄與持久化，不被後續連鎖跳機覆蓋。
5. 操作員以 Reset Key `0xA55A` + 新命令序號 + Reset Coil 脈衝重置，
   且所有安全條件（含遲滯與 reset_delay）必須成立。
6. 重置後設備回到 OFF；**被 STOP 過的設備需要再按一次 START** 才會恢復自持運轉，
   其餘設備允許條件一成立就自己回來。

## 5. 測試前的環境重置

```bash
plantctl snapshot restore steady-60mw --clean   # 毫秒級，容器不重啟
```

比起 `docker compose down && up`（分鐘級、Modbus 連線中斷、累積量歸零），
快照還原能讓每個測試都從位元級相同的起點開始。`--clean` 同時會解除操作員停機鎖，
因此還原後機組會自己回到運轉狀態。
